# 0.1.16：iMessage 授权与转发可靠性

## 本次修复

- 原实现丢弃显式授权读取的目标，界面刷新与后续发送又进行无交互读取；系统只允许一次时会重新失败。本版仅在当前进程保留显式授权／保存的目标，关闭转发、睡眠、退出或更改目标时清除，不修改钥匙串 ACL、不存明文文件。
- 授权后自动检查 Messages 连接，不发送；保存目标不再阻塞主线程，失败时保留输入。
- 队列发送前使用 SQLite 原子占位。重复扫描与并发任务不能再次提交正在发送的同一条消息。
- 未预期发送异常立即标为“发送结果不确定”，不自动重发或清理。单独的“重试失败项”仅处理失败，不修改不确定记录。
- 转发开关和实际健康状态分开显示，不再用“已开启”代表链路正常。

## 验证

- Ruff、mypy 通过；331 项测试通过，1 项 Windows Tk 测试在 macOS 跳过。
- 配置范围覆盖率 92.86%，选定核心模块 95%；AppKit 打包 UI、arm64、签名完整性、DMG 只读挂载及 SHA-256 通过。
- 回归包含一次授权后的刷新／后台读取、缓存撤销、授权中睡眠、写入失败、并发发送、异常不重发、仅重试失败项，以及 Wi-Fi 下数据关闭的 PDU 解码至转发流程（模拟 USB 与 Messages 边界）。
- 实机验收应使用隔离模式，不扫描短信、不自动转发、不删除模块短信、不控制 4G。
- 系统钥匙串授权及收件端实际送达须单独验收；自动化通过不能描述为端到端送达通过。本机诊断数据不纳入公开报告。

## 权限与限制

无新依赖或权限；不访问 Messages 数据库，不记录正文或完整目标，不放宽 macOS 安全策略。包仍为 ad-hoc 签名、未公证，版本更新后系统可能要求再次授权。Messages 接受请求不代表收件端已送达。不确定历史记录必须由用户在“信息”核对后决定是否重发。
